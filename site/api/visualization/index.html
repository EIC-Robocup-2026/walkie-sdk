    Visualization¶

    RViz2 marker publishing for debugging and visualization. Access via bot.viz.

    Marker Type Constants¶

    Constant Value Description
    ARROW 0 Arrow marker
    CUBE 1 Cube marker
    SPHERE 2 Sphere marker
    CYLINDER 3 Cylinder marker
    LINE_STRIP 4 Connected line segments
    LINE_LIST 5 Pairs of line segments
    CUBE_LIST 6 List of cubes
    SPHERE_LIST 7 List of spheres
    POINTS 8 Point cloud
    TEXT_VIEW_FACING 9 Billboard text
    MESH_RESOURCE 10 Mesh file
    TRIANGLE_LIST 11 Triangle mesh

    Import these from the top-level package:

    from walkie_sdk import SPHERE, ARROW, CUBE

    API Reference¶

    Visualization(transport, namespace='') ¶

    RViz2 marker visualization controller.

    Provides methods to publish visualization markers that can be displayed in RViz2. Supports single markers and marker arrays.

    This class works with any transport that implements ROSTransportInterface, making it protocol-agnostic (works with rosbridge, zenoh, etc.).

    Parameters:

    Name Type Description Default
    transport ROSTransportInterface

    Transport instance implementing ROSTransportInterface

    		 required
    namespace str

    ROS namespace prefix for topics (default: "" = no namespace)

    		 ''
    Example 
    viz = Visualization(transport, namespace="robot1")
viz.draw_marker(
    position=[1.0, 2.0, 0.0],
    quaternion=[0.0, 0.0, 0.0, 1.0],
    frame_id="base_link",
)

    namespace property writable ¶

    Current ROS namespace.

    draw_marker(position, quaternion=None, frame_id='base_link', marker_type=ARROW, scale=None, color=None, marker_id=None, lifetime=0.0, ns='', text='', frame_locked=False, topic=DEFAULT_MARKER_TOPIC) ¶

    Publish a single visualization marker to RViz2.

    Parameters:

    Name Type Description Default
    position List[float]

    [x, y, z] position in the reference frame.

    		 required
    quaternion Optional[List[float]]

    [x, y, z, w] orientation quaternion. Defaults to identity [0,0,0,1].

    		 None
    frame_id str

    TF reference frame (default: "base_link").

    		 'base_link'
    marker_type int

    Marker shape type (default: ARROW). Use module constants: ARROW (0), CUBE (1), SPHERE (2), etc.

    		 ARROW
    scale Optional[List[float]]

    [sx, sy, sz] marker scale in meters. Defaults: ARROW=[0.2, 0.05, 0.05], others=[0.1, 0.1, 0.1].

    		 None
    color Optional[List[float]]

    [r, g, b, a] color (0.0-1.0). Default: [1.0, 0.0, 0.0, 1.0] (red).

    		 None
    marker_id Optional[int]

    Unique ID for this marker. Auto-assigned if None. Publishing with the same ID replaces the previous marker.

    		 None
    lifetime float

    How long the marker persists in seconds (0 = forever).

    		 0.0
    ns str

    Namespace string for grouping markers in RViz2.

    		 ''
    text str

    Text content (only for TEXT_VIEW_FACING markers).

    		 ''
    frame_locked bool

    If True, marker is re-transformed each frame.

    		 False
    topic str

    ROS topic to publish on (default: "walkie/viz_markers").

    		 DEFAULT_MARKER_TOPIC

    Returns:

    Type Description
    int

    The marker ID that was used (useful when auto-assigned).

    Raises:

    Type Description
    ConnectionError

    If not connected to ROS transport.
    Example 
    # Draw a red arrow at position (1, 2, 0)
viz.draw_marker([1.0, 2.0, 0.0])

# Draw a green sphere with custom scale
viz.draw_marker(
    position=[3.0, 0.0, 0.5],
    quaternion=[0.0, 0.0, 0.0, 1.0],
    frame_id="map",
    marker_type=SPHERE,
    color=[0.0, 1.0, 0.0, 0.8],
    scale=[0.2, 0.2, 0.2],
)

    update_marker(marker_id, position=None, quaternion=None, frame_id=None, marker_type=None, scale=None, color=None, lifetime=None, ns=None, text=None, frame_locked=None, topic=DEFAULT_MARKER_TOPIC) ¶

    Update an existing marker with only the changed fields.

    Merges the provided parameters with the cached values from the original draw_marker() call, then republishes. Only pass the fields you want to change.

    Parameters:

    Name Type Description Default
    marker_id int

    ID of the marker to update (must have been created with draw_marker()).

    		 required
    position Optional[List[float]]

    New [x, y, z] position (or None to keep current).

    		 None
    quaternion Optional[List[float]]

    New [x, y, z, w] orientation (or None to keep current).

    		 None
    frame_id Optional[str]

    New reference frame (or None to keep current).

    		 None
    marker_type Optional[int]

    New marker type (or None to keep current).

    		 None
    scale Optional[List[float]]

    New [sx, sy, sz] scale (or None to keep current).

    		 None
    color Optional[List[float]]

    New [r, g, b, a] color (or None to keep current).

    		 None
    lifetime Optional[float]

    New lifetime in seconds (or None to keep current).

    		 None
    ns Optional[str]

    New namespace (or None to keep current).

    		 None
    text Optional[str]

    New text content (or None to keep current).

    		 None
    frame_locked Optional[bool]

    New frame_locked flag (or None to keep current).

    		 None
    topic str

    ROS topic the marker was published on.

    		 DEFAULT_MARKER_TOPIC

    Raises:

    Type Description
    ConnectionError

    If not connected to ROS transport.
    KeyError

    If the marker_id was not previously created with draw_marker().
    Example 
    # Create a marker
mid = viz.draw_marker([0, 0, 0], [0, 0, 0, 1])

# Update only its position (everything else stays the same)
viz.update_marker(mid, position=[1.0, 2.0, 0.0])

# Update position and color together
viz.update_marker(mid, position=[3.0, 0.0, 0.0], color=[0, 1, 0, 1])

    draw_markers(markers, topic=DEFAULT_MARKER_ARRAY_TOPIC) ¶

    Publish multiple markers as a MarkerArray to RViz2.

    Parameters:

    Name Type Description Default
    markers List[Dict[str, Any]]

    List of marker parameter dicts. Each dict accepts the same keyword arguments as draw_marker(): - position (required): [x, y, z] - quaternion: [x, y, z, w] (optional, default identity) - frame_id: str (default: "base_link") - marker_type: int (default: ARROW) - scale: [sx, sy, sz] - color: [r, g, b, a] - marker_id: int (auto-assigned if omitted) - lifetime: float - ns: str - text: str - frame_locked: bool

    		 required
    topic str

    ROS topic to publish on (default: "walkie/viz_markers_array").

    		 DEFAULT_MARKER_ARRAY_TOPIC

    Returns:

    Type Description
    List[int]

    List of marker IDs that were used.

    Raises:

    Type Description
    ConnectionError

    If not connected to ROS transport.
    Example 
    viz.draw_markers([
    {
        "position": [1.0, 0.0, 0.0],
        # quaternion defaults to identity
        # marker_type defaults to ARROW
        "color": [1.0, 0.0, 0.0, 1.0],
    },
    {
        "position": [2.0, 0.0, 0.0],
        "marker_type": SPHERE,
        "color": [0.0, 1.0, 0.0, 1.0],
    },
])

    draw_pose(position, quaternion=None, frame_id='base_link', topic=DEFAULT_POSE_TOPIC) ¶

    Publish a PoseStamped message to RViz2.

    This publishes a geometry_msgs/msg/PoseStamped on the specified topic, which can be visualized in RViz2 using the built-in "Pose" display type. Use different topics for different poses (e.g. one per arm group).

    Parameters:

    Name Type Description Default
    position List[float]

    [x, y, z] position in the reference frame.

    		 required
    quaternion Optional[List[float]]

    [x, y, z, w] orientation quaternion. Defaults to identity [0,0,0,1].

    		 None
    frame_id str

    TF reference frame (default: "base_link").

    		 'base_link'
    topic str

    ROS topic to publish on (default: "walkie/target_pose"). Use unique topics for multiple simultaneous poses, e.g. "walkie/target_pose/left_arm".

    		 DEFAULT_POSE_TOPIC

    Returns:

    Type Description
    str

    The topic string that was used (useful for later update_pose() calls).

    Raises:

    Type Description
    ConnectionError

    If not connected to ROS transport.
    Example 
    # Draw pose with default identity orientation
viz.draw_pose([1.0, 2.0, 0.0])
# returns 'walkie/target_pose'

# Multiple poses on different topics
viz.draw_pose(
    position=[0.5, 0.0, 0.3],
    quaternion=[0.0, 0.0, 0.0, 1.0],
    topic="walkie/target_pose/left_arm",
)
# returns 'walkie/target_pose/left_arm'
